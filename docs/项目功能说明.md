# 数据共情者｜项目功能说明

## 1. 项目定位

“数据共情者”是面向美妆电商客服的 AI 接待与风险辅助平台，采用模拟千牛工作台形态：

```text
左侧导航/会话队列 | 中间客服聊天 | 右侧 AI 接待辅助
```

系统融合聊天记录、订单、五类售后工单、知识资料和图片附件，帮助客服快速理解消费者当前诉求、历史服务和风险状态。

本项目是本地可运行 Demo，不接入真实千牛，不执行真实退款、打款、退货、补发、换货或订单修改。

## 2. 页面与入口

左侧保留七个入口：

- 客户视角
- 客服工作台
- 风险预警
- 工单管理
- 知识库
- Prompt 管理
- 模型配置

### 客户视角

- 新建和切换多个会话。
- 发送文字和图片。
- 查看客服或 AI 回复。
- 转人工。
- 查看普通聊天状态。

客户侧不展示风险、情绪标签、知识依据、Prompt 和工单操作。

### 客服工作台

客服工作台是主要演示页面，包含：

- 会话队列、未读状态和服务模式。
- 中间聊天区，区分消费者、客服和 AI 消息。
- 当前订单、物流和售后工单。
- 交接摘要。
- 当前消费者情绪和风险。
- AI 回复建议。
- 个性化商品/护理建议。
- 消费者服务档案。
- 图片可见信息和原图入口。
- 服务记忆、知识依据和服务轨迹。

### 风险预警

风险看板回答：

```text
谁需要关注？为什么？现在应该做什么？
```

支持：

- 风险等级和当前状态。
- 情绪升级、投诉、重复进线、重复退款/退货、不良反应、服务断点、未回复和跟进临期等信号。
- 风险证据和最新消费者原话。
- 直接打开对应会话。
- 接管处理、开始处理、复核关闭和忽略。
- 误报/确认风险/信息不足判断。
- 服务轨迹、历史进线、关联工单。
- 情绪弧线。
- 历史风险敏感度提示。

风险状态和工单状态相互独立。工单完成不会自动关闭风险。

### 工单管理

独立管理五类源工单：

- 补发换货
- 线下打款
- 物流
- 不良反应
- 售后退货

支持本地跟进、负责人、优先级、期限、备注、状态流转和待办筛选。人工录入的本地跟进不会覆盖官方源事实，也不代表真实售后已经执行。

### 知识库

- 创建知识库文档。
- 导入 Markdown/TXT。
- 编辑正文和商品关联。
- 预览切片。
- 显式发布知识索引。
- 启停文档。
- 检索测试。

知识库用于回复依据，不替代订单或工单事实。

### Prompt 管理

- 管理自动接待、接待辅助和安全校验用途。
- 编辑和启停模板。
- 绑定生效模板。
- 查看历史版本。
- 恢复历史版本。

Prompt 修改后旧建议会失效，但固定安全、引用和人工确认规则不会被关闭。

### 模型配置

- 配置文本模型。
- 配置视觉模型。
- 配置向量模型。
- 配置重排序模型。
- 查看真实能力状态。
- 测试模型连通性。

模型不可用时显示失败并转人工，不静默使用成功 Mock。

## 3. AI 自动接待

### 自动接待模式

普通消费者消息进入后台接待任务，由真实模型生成并自动发送回复。

发送前会检查：

- 当前会话模式。
- 消息版本。
- 模式版本。
- 来源和订单/工单关联。
- 回复引用。
- 安全边界。
- 知识检索状态。

### 人工模式

以下情况停止 AI 自动发送：

- 客户要求转人工。
- 客服主动接管。
- 高风险不良反应。
- 投诉或安全条件触发。
- 模型、知识库或事实核验失败。
- 超过总等待时间。

人工模式下 AI 只生成草稿，客服点击采用后写入回复框，仍需客服单独发送。

## 4. 多源服务上下文

Agent 会读取：

- 当前聊天和历史聊天。
- 关联订单。
- 五类售后工单。
- 本地跟进工单。
- 消费者服务记忆。
- 知识库资料。
- 图片观察结果。

消费者记忆分为：

- 已知信息
- 消费者关注
- 已尝试措施
- 待解决事项

记忆保留来源和原文，不把客服承诺当成业务执行事实。

## 5. 个性化与共情

### 个性化建议

系统会结合消费者本轮表达、历史记忆和知识资料，识别：

- 肤质和分区困扰。
- 对妆感、厚重、卡粉等问题的关注。
- 已经尝试过的措施。
- 不希望重复的操作。
- 对商品推荐的明确偏好。

有明确商品资料时，建议区分商品身份、来源、市场和资料范围；资料不足时不猜测功效、成分或适用性。

### 回复共情维度

每条回复建议显示三个维度：

- **情绪回应**：是否承接消费者的担心、不满或焦虑。
- **业务处理**：是否给出当前问题相关的信息或下一步。
- **个性化**：是否使用了消费者本轮明确提供的信息。

这些是可解释的辅助标签，不是人工专家评分，也不代替客服判断。

### 消费者服务档案

客服可以看到同一消费者的历史进线：

- 历史进线时间。
- 最近消费者诉求。
- 历史客服回复。
- 是否关联同一订单。
- 是否可能是同一服务主题。

系统只使用明确订单、会话和工单关系，不把脱敏昵称当成身份认证。

## 6. 图片接待

图片处理链路：

```text
上传校验 → 保存附件 → 视觉模型读取 → 保存图片观察 → 回复引用 → 客服查看原图
```

支持：

- 标签和批次号文字。
- 物流/订单截图中可见文字。
- 包装上的可见现象。
- 后续追问复用同一图片观察。

限制：

- 图片观察不等于订单系统事实。
- 图片不能证明正品、生产日期、签收、退款到账或个人适用性。
- 图片模糊、皮肤/就医图片或事实冲突时转人工。

## 7. 风险与情绪

风险规则会结合：

- 当前消费者情绪。
- 最近情绪变化。
- 消费者原话。
- 多次进线。
- 订单和工单状态。
- 客服/AI 是否实际回复。
- 服务断点分析。
- 历史情绪升级和投诉记录。

风险详情中的情绪弧线展示：

- 每条消费者消息的情绪点。
- 情绪起点。
- 情绪转折次数。
- 当前情绪。
- 关键转折原话。

历史风险敏感度只提高客服关注优先级，不改变风险等级，也不自动处置风险。

## 8. 数据与安全边界

- 官方 Excel 数据为虚构业务数据。
- 原始订单、聊天和工单事实不可被模型覆盖。
- 运行数据存放在 `data/runtime`，不入 Git。
- API Key 只保存在后端。
- 客户接口不能读取内部风险和知识依据。
- 不执行真实售后动作。
- 不做医学诊断。
- 不接入真实千牛。
