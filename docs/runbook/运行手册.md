## 启动

双击代码根目录的 `start-demo.cmd` 即可启动前后端，成功后自动打开客服工作台。不要求先激活虚拟环境或切换终端目录；需已安装 Node.js/npm 与 uv。前端依赖缺失时自动执行 `npm ci`，后端保持非editable同步。重复启动复用本项目已运行服务，不结束其他项目进程，不清空数据、不改模型配置。失败时窗口保留原因和日志位置。

后端：

```powershell
cd D:\作业\安克黑客松\2项目开发\code
.\scripts\start_loreal_backend.ps1
```

需要同时启动后端和前端时，可从代码根目录执行：

```powershell
.\scripts\start_loreal_demo.ps1
```

该脚本只启动缺失的服务，不结束未知进程；确认API、前端页面及前端API代理都可访问后才报告成功。添加 `-OpenBrowser` 自动打开客服页面；任一服务失败会保留已运行服务并提示对应日志。

需要后台常驻时使用 `.\scripts\start_loreal_backend.ps1 -Background`。该模式隐藏窗口，输出实际PID，并把日志保存在 `data/runtime/logs/backend.stdout.log` 和 `backend.stderr.log`，不依赖当前交互终端。脚本会禁用用户 site 并检查虚拟环境残留 editable `.pth`，避免中文路径下 Python 在 `init_import_site` 阶段失败。启动观察窗口结束不代表进程已停止；先检查8000监听及日志，不重复启动或结束其他进程。

源码变更后需要重新加载时使用 `.\scripts\start_loreal_backend.ps1 -Background -Restart`。脚本只会在确认8000由本项目的 `uvicorn app.main:app --port 8000` 进程占用时重启；端口由其他进程占用、多个进程监听或旧进程未释放端口时会拒绝操作。

脚本会先检查8000是否已有健康后端；没有运行时执行 `uv sync --extra dev --no-editable`，再以UTF-8模式启动Uvicorn。模型凭证使用现有后端配置，不输出密钥。

如果出现 `Fatal Python error: init_import_site` 或 `UnicodeDecodeError: 'gbk' codec can't decode`，
说明虚拟环境仍残留中文路径的 editable `.pth`。重新执行启动脚本，或手动执行 `uv sync --extra dev --no-editable`，
确认 `.venv\Lib\site-packages\` 下没有 `_editable_impl_*.pth` 后，再启动 Uvicorn。
脚本遇到健康的已有服务只报告状态，不重启或热加载。修改 Python 源码后，
在原后端终端按 `Ctrl+C`，等待退出，再重新执行启动脚本；不要重复启动占用同一端口的进程。
依赖同步失败时脚本终止，不继续启动。8000被其他服务占用时明确报错，不结束其他进程。

## 数据与知识

### 接待与交接

客服辅助默认先展示交接摘要与回复建议，摘要合计2–5句；无生成缓存或缓存过期时用当前会话原文提供交接，明确“客户反馈/客服曾回复”，不把历史客服发言当业务执行证明。客服明确接管后生成当前人工草稿，采用仍只填输入框，不发送。查询页面本身不新增模型调用。

图片接待复用现有附件接口和已配置视觉模型。图片先校验实际格式并落盘，再由 `IMAGE_OBSERVATION_V1` 读取可见文字/现象；观察结果按附件哈希、消息、分析版本和视觉模型保存，后续追问复用，不重复读图。回复必须写“照片上/图中/截图显示”，图片文字不能证明订单已签收、退款到账、正品、生产日期或个人适用性；图片不清、皮肤/就医图片或图片与业务事实冲突时转人工。客服在“更多信息”查看图片可见信息和原图，客户侧只看到图片与正常消息。

客服右侧回复建议显示三项共情维度：情绪回应、业务处理、个性化。服务档案显示同一消费者的历史进线、最近诉求、历史客服回复、订单关系和同一诉求提示。风险详情的服务轨迹显示情绪弧线；风险排序可显示历史风险敏感度，仅影响关注优先级，不改变风险状态。话术采用率统计按当前范围暂不实现。

消费者话术约束在`reply_policy.py`，对自动接待和人工草稿同样生效，位于已保存模板之后，不覆盖用户自定义Prompt。语气参考官方Excel的S00090/S00474历史对话，但不照搬未验证的成分、孕期保证、退款时限或真实操作承诺。客户回复不含工单号、本地状态和能力免责声明；实际未知项仍简短说明。

起草与核验共同读取`currentServiceContext`，消息/订单/售后来源含明确关联字段；历史同昵称订单不当当前订单。修改该约束会更新工作流版本和来源哈希，使旧建议失效，不重写历史消息。S00381的旧退款金额引用错误与后续核验串单均保留失败记录；最终主页面生成证据为`evals/results/loreal-official-support-final-20261004T100701Z.json`。

### 共情展示

客服右侧回复建议会显示三个可解释维度：情绪回应、业务处理、个性化。维度来自当前回复与当前消费者上下文的结构化检查，不代表人工专家评分，也不参与风险状态改变。

服务上下文中的“消费者服务档案”展示历史进线、最近消费者原话、历史客服回复、同订单关系和同一诉求提示，用于减少重复询问；它只读取明确数据关联，不把脱敏昵称当作身份认证。

风险详情的“服务轨迹”包含情绪弧线：按消费者消息时间和固定情绪枚举展示起点、转折和当前情绪。风险排序可显示历史风险敏感度，来源是同一消费者历史情绪升级/投诉记录，仅增加客服关注优先级，不改变风险等级、风险状态或自动处置。

本批不实现话术采用率、修改率统计；已有采用/忽略操作审计不等同于统计看板。

风险关注卡仅展示当前会话的未关闭信号并合并同类提醒。介入只调用原子接口，不回退或本地伪装风险状态；转人工并不等于风险已处理。风险详情“服务排查”默认收起，通过会话选择器排查重复追问、承诺待兑现、完结后问题仍未解决，不逐会话堆面板，不自动调用模型。

起草与核验使用提供者已有的JSON对象输出能力；建议字段的实际Pydantic结构和引用字段规则随起草请求提供。建议引用的错误带`personalized_advice[index]`及对应字段名，回复引用仍反馈`body`。这是格式引导，不是API端的严格JSON Schema约束，也不替代来源和独立核验；空JSON、截断或无依据结果仍拒绝，不回退成成功Mock。

完整JSON的字段校验失败时，原对象只保留在本次工作流内存，供一次修正按原稿和明确长度/数值界限修改；不进缓存、日志、审计或客户响应。不是完整JSON对象时不保存修正上下文，不扩大重试次数。v2.26真实R01仍未通过；v2.27这项修正上下文行为有定向检查，未再次调用模型。

### 引用话语片段

v2.28起，模型优先输出回复`segments`及建议`action_parts/rationale_parts`，每段同时包含消费者可读话语和模型明确选择的`source_refs`；程序直接拼接并生成原有`body/action/rationale/claims`，不再让模型重复复制正文作引用。没有来源的片段不自动补来源，事实缺引用仍被拦截；来源选错或不支持内容仍需修正并独立核验。回复8段各100字符，建议行动3段各80字符、理由3段各60字符，原总长度界限不变。

客服插件的`personalizedAdvice`同时返回建议claims。证据卡先显示模型显式登记的消费者/知识摘录，再按同一建议claims实际引用的知识来源补充完整商品资料摘录；不从商品名或相似度推断来源，旧缓存没有claims时保持为空。公开来源网址存在时只用于去掉登记头部、保留正文和限制；缺网址则保留原始片段。

v2.32起，检索结果内部额外保留已选中片段的完整`source_texts`，起草和独立核验的`sourceCatalog.text`不再使用400字符界面摘录。重排序后按片段ID对应，不带入未选中资料；完整片段仍受原60000字符来源预算限制。对外`knowledgeEvidence`保留短摘录，不额外复制内部正文字段；`groundingSources`及实际引用的建议证据保留完整片段供客服查证。比较任务增加先给结论、不附加未请求护理和不重复堆砌资料的指导；没有新的真实模型复测，不能把v2.31报告算作v2.32简洁性或完整来源效果证明。

旧`body/claims`和`action/rationale/claims`格式仍可读取；同一对象混用非空旧字段和分段格式时拒绝，防止忽略另一个正文。对外API及缓存仍只保存原展示结构，内部话语分段不泄露到客户侧。格式变更不增加模型节点、重试次数或业务权限。

## 消息与辅助

- 新建客户会话默认AI自动接待。客户消息先落库并返回，后台队列随后调用真实模型并自动发送回复，不需要客服点击生成或采用。
- 客户可点击“转人工”或明确发送转人工诉求；客服可“接管会话”。转人工后取消队列任务并阻止生成中旧结果发送；客服必须明确“恢复AI接待”才重新托管，恢复不重放已处理消息。
- 自动接待、人工模式的建议生成分别使用 `LOREAL_AUTO_REPLY` 和 `LOREAL_ASSISTANT`，共享 `LOREAL_SAFETY`。三个用途均可在Prompt页绑定自定义模板。
- 后台最多同时处理4个会话，任务持久化在 `service_auto_reply_job`。连续新消息合并待执行任务；重启恢复未完成任务，但过期任务转人工。
- 自动发送前校验消息版本、模式版本和关联上下文哈希，并在数据库写锁内插入消息；重复提交和重复执行不能多发。
- `ANKER_AGENT_AUTO_REPLY_TIMEOUT_SECONDS` 默认45秒，包括排队和生成。起草、核验、修正各次模型请求只得到剩余时间，不各自重置45秒；发送前来源哈希复核完成后再次检查期限。耗尽时停止后续调用并转人工，不发送迟到回复。已经阻塞的线程不能强制终止，检索仍受自身请求超时约束，但晚结果不会继续触发模型/发送。模型不可用、校验失败或高风险也转人工；图片模型不可用、图像不清、皮肤/就医图片或图片与业务事实冲突时转人工。
- 模型主动转人工时，先发送通过校验的具体说明，再发送系统转人工通知；用户已先接管时，不补发迟到的模型内容。
- 模型Chat Completions改用已安装的httpx；请求不继承系统/环境代理，不修改操作系统代理设置。原urllib链路在当前机器上出现超时，同一服务通过新HTTP客户端已实测可用。
- 客服页按一秒周期同步统一队列，展示未读；实际加载消息后才标已读。
- 统一接待队列接口为 `GET /api/support/reception/queue`，返回 `items`；`service-queue` 仅提供官方导入会话，不用于验收本地实时接待。当前情绪、活动风险和待复核风险来自最新消费者消息及程序信号，不依赖先生成AI建议。
- 客户页同步客服回复。官方历史消息与后续消息分开保存。
- `GET /api/support/conversations/{id}/assistant` 只读缓存。
- 客服插件“风险关注”通过 `GET /api/support/desk/conversations/{id}/risks` 独立读取最新风险，不依赖AI建议缓存、不调用模型、不扫描或处置风险。范围只限当前会话及其明确关联订单，不按昵称合并。插件打开时加载，消息/风险类型变化时更新，每10秒及窗口重新聚焦时回读；隐藏的插件停止轮询。
- 未关闭信号显示原因、当前处置/复核状态和下一步，临期事项显示工单号与期限；已关闭信号移出关注区。链接携带明确风险事件编号，可打开其他来源会话但同一订单的风险详情。风险读取失败仅影响风险区域，不阻断聊天、草稿或AI建议；切换会话后忽略旧请求。
- `POST /api/support/reception/{id}/assistant` 才调用模型及欧莱雅知识检索。
- `personalizedAdvice` 是共同核验后的通用建议，最多2项，分类为`routine`、`makeup`、`product_selection`、`trial_safety`；每项带`scope=general_consumer`及逐字证据。无方案依据、转人工或非当前美妆话题时为空，商品证据缺口放在回复而非伪装成方案。旧缓存字段缺失默认空数组，工作流版本升级使旧缓存过期。
- 消费者本轮明确不再做清洁/保湿时，正文和建议都检查重复措施；已试过的描述与否定说明保留。该门禁只处理明确文字，复杂语义仍由模型核验。草稿契约失败只记录字段路径/错误类型，不保存完整模型值。
- 采用只填写草稿并记审计；发送为独立动作。消息、Prompt 或索引变化会使旧建议过期。
- 工单页展示官方五类源工单与本地跟进记录；风险页展示程序预警及客服处理记录。
- 风险页区分三种状态：`仍在触发`表示规则当前仍有信号，`待复核`表示触发条件已消退或分析资料需要人工判断，`已关闭`表示客服已完成风险处置。`待介入/处理中/已处理`仍是客服处置状态，不与触发是否持续混用。
- “人工复核”只记录单条信号是真风险、误报或信息不足，不完成工单、不关闭风险；“处置记录”记录客服对风险事件的介入、关闭、忽略和说明；“历史轮次”保留人工关闭的不可变快照。
- 重复进线按数据里的脱敏昵称与店铺（本地会话使用Demo消费者标识）及观察窗口计算，默认72小时；不是实名身份验证，也不能单凭进线次数断言同一诉求未解决。旧记录缺少窗口/明细时，不补造命中结论；详情的 `contactHistory` 单独展示关联历史首条消息，不合入信号 `evidenceRefs`、条件或人工判断快照。
- 服务断点分析单独运行断点候选、证据门禁和语义核验，不依赖客服回复起草；客服回复核验失败不会再把断点分析显示成“回复依据核验未通过”。
- 情绪升级由规则判断：导入时和客户每条新消息后执行，不调用模型；客户页新会话同样会生成预警。

### 服务记忆与事实核验

- `consumer_service/grounded_workflow.py` 使用LangGraph编排：来源收集、知识检索、起草、确定性字段检查、独立模型核验、输出确认。最多修正一次，修正复用检索结果。
- 原始订单/工单、客户自述、历史客服发言、本地跟进、知识分开标注来源；本地AI回复仅作为最近48条对话背景，不进入事实目录。来源正文总量超过60000字符时明确拒绝自动生成。
- 记忆保存在 `service_memory`，每项包含类型、来源及逐字原文，更新输入后标记过期；`GET /api/support/reception/{id}/memory` 仅客服可读。当前记忆不是永久消费者健康标签。
- 回复的具体事实需引用来源，校验编号、金额、日期、状态与错单归因，再使用独立模型请求核对语义、摘要及记忆。模型核验不是外部独立评测，仍可能误判。
- `service_assistant_run` 保存节点、实际Token和输入字符数（`modelUsage.inputCharacters`）；字符数不是Token，不换算成费用。修正节点最多8条、每条200字符的问题，不存完整Prompt/模型输出。核验失败不写新记忆/建议；失败网络请求Token记未知，晚返回的已发生调用和格式错误仍记用量。
- 起草的`memorySourceCatalog`只列sourceId/kind，原文和字段在`sourceCatalog`完整保留，核验步骤仍读取全部来源。`evals/results/loreal-payload-shape-20261002.json`只比较该重复字段，两例减少2710/400字符，不证明全流程Token或成本收益。
- 起草和独立核验接收 `serviceCapabilities`：只读已有订单/工单，不接实时物流、不主动后续跟进、不执行售后。允许补充订单号后再次查询已有记录，不允许承诺查询实时派送进度；客户回复不得展示内部状态码。“不会猜测成分”不作确定商品断言，但同句真实商品结论仍须引用。
- 主应用及隔离评测的关闭流程等待仍在执行的线程任务后再关闭数据库；只取消asyncio任务不会中断正在执行的模型请求。
- 自动模式只生成推荐回复，人工模式可生成多种候选。接管/新消息淘汰任务后，不继续调用核验模型，也不发送旧回复。
- 只读浏览器检查：`node e2e/_walk-grounded-memory.mjs <已有核验结果的会话ID>`，检查1440/1280/390下记忆与节点展示，不发送消息或调用模型。

### 服务断点分析

- 风险页的“分析会话”读取客服队列，不调用模型；选择会话后点击“分析服务断点”才调用独立断点分析链路。
