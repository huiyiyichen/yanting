### 0.2 不得改变的边界

沿用《赛道对照改进方案》0.1 节：

1. AI 接待模式可自动发送普通回复；人工模式的 AI 内容只填草稿，客服确认发送。
2. 不自动执行退款、打款、退货、补发、换货；不做医学判断。
3. 风险状态只由规则和客服改变；工单完成不自动关闭风险。
4. 官方源事实不可改写。
5. 客户页不展示情绪、风险、依据、Prompt、AI 控制项。
6. 界面只有标题、字段、状态、按钮、图例和业务数据，不加说明性文字。
7. 验收遵守 `AGENTS.md` v2.4：端到端用例优先；不在实现后补写单元测试；需要隔离验证的部分先列失败方式再实现；产物放 `code/output/playwright/<板块>/`。

## 1. 视觉元素与动效规范

### 1.1 三种情绪画法

同一份情绪数据，按观察尺度分工，**同一视图里同一次会话只用一种画法**：

| 画法 | 尺度 | 编码 | 用在 |
|---|---|---|---|
| 情绪声纹（已有） | 多会话汇总 / 单会话缩略 | 柱子高度与颜色表示情绪强度 | 风险页主图、风险列表“情绪走势”、插件画像卡 |
| 情绪色号（新增） | 单会话，与其他会话并列比较 | 每条消费者消息一段色带，最新一段加高 | AI 接待全景、风险详情服务轨迹 |
| 服务乐谱（新增） | 单会话完整经过 | 双方消息、情绪高低、等待、升降温 | 风险详情“对话回放” |

### 1.2 颜色与令牌

- 情绪三色、香槟金、深浅两套底色沿用《赛道对照改进方案》5.2 节令牌。
- 颜色只表达情绪和风险；香槟金只用于品牌、AI 和服务方；其他类别用中性色加文字。
- 浅色下“不满”橙对白底对比度 2.77:1，必须伴随文字或可读的等价信息。
- 本文新增令牌：

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--yt-staff` | `#e3dce9` | `rgba(236,224,245,0.12)` | 乐谱线、泳道分隔 |
| `--yt-silent` | `#c9c0d2` | `#5a4d66` | 未发生的步骤、空泳道占位 |
| `--yt-service` | `#8a6532` | `#d9b47c` | 乐谱服务方音符、AI 状态 |

### 1.3 动效规范

| 类别 | 时长 | 说明 |
|---|---|---|
| 微反馈（按钮、选中） | 120–200ms | — |
| 布局变化（位移、展开） | 280–560ms | 位移用 FLIP，缓动 `cubic-bezier(.2,.8,.2,1)` |
| 内容生长（色带长出、下划线画出） | 180–420ms | 从数据方向生长 |

- 每个页面最多一个自动播放的动画：风险页是声纹升起；全景是 AI 处理中的声纹律动（表示真实状态，不算装饰）。其余动画只在用户操作或真实事件发生时出现。
- `prefers-reduced-motion` 下关闭全部过渡和律动，状态用静态样式表达。
- 不做：数字滚动计数、霓虹发光、粒子背景、大面积毛玻璃、每个区块的入场动画。

### 1.4 全局明暗（反馈 ⑦）

- 顶栏右侧增加明暗切换，默认跟随系统，选择保存在本地。
- 风险页在两种模式下都可用；工作台、全景、工单、知识库、Prompt、模型配置页补深色令牌。
- 客户页始终浅色（面向消费者）。
- 验收：每页深浅两套截图，无白色残留卡片、无看不见的提示字。

## 2. 共享组件

### 2.1 情绪色号 `features/voiceprint/EmotionSwatch.tsx`

```
  ╱▔▔▔▏  ← 斜切顶（口红斜面），时间从上往下
 ▕░░░░▏  不满
 ▕▓▓▓▓▏  激烈
 ▕████▏  平稳   ← 最新一段，占 40% 高度
 ▕████▏
  ▔▔▔▔
```

| 项 | 规则 |
|---|---|
| 输入 | `bands: EmotionLevel[]`（按时间顺序）、`highRisk`、`size` |
| 色带 | 每条消费者消息一段，最多显示最近 6 段；一段时占满，多段时最新一段占 40%，其余平分 60%；段间 1.5px 背景色间隔；不做渐变混色 |
| 外形 | `clip-path: path(...)` 裁切：左上比右上低 7px，底部圆角 5px |
| 尺寸 | `lg` 40×66（预览头部）、`md` 32×54（全景）、`sm` 12×20（服务轨迹） |
| 高风险 | 右上角 9px 风险色圆点，2px 背景色描边 |
| 投影 | `md` 尺寸底部加柔和椭圆投影（像摆在货架上），`sm` 不加 |
| 可访问 | `role="img"`，`aria-label` 写出情绪序列，如“不满、激烈、平稳，高风险” |
| 动效 | 新增一段时，该段从底部长出 420ms |

### 2.2 服务乐谱 `features/voiceprint/ServiceScore.tsx`

把一次会话画成两行乐谱：上一行消费者，下一行服务方。

```
          10:15          10:18              10:21          10:25
消费者  激烈 ─────────────────●^─────────────────────────────────────
        不满 ──────●─────────────────────────────●───────────────────
        平稳 ─────────────────────────────────────────────────●──────
                    ◁━━━━━━━━━━━━▷        ◁━━━━━━━━━━  ◁━━━━━━━
服务方  ────────────────■──────────▬▬■──────────────▬▬▬■────────────
                       10:18        10:20 2′          10:24 3′
```

| 元素 | 编码 | 画法 |
|---|---|---|
| 消费者音符 | 情绪 = 音高 | 三条谱线：平稳 / 不满 / 激烈，间距 22px；音符为倾斜 20° 的椭圆 9×7，填情绪色，2px 背景色描边 |
| 触发音符 | 触发了风险信号的消息 | 音符上方加重音记号 `^`（风险色） |
| 渐强 / 渐弱 | 相邻两条消费者消息之间情绪升 / 降 | 画在消费者谱下方；升温用激烈色、降温用平稳色；不变不画 |
| 服务方音符 | 客服或 AI 回复 | 人工实心方块，AI 空心方块，颜色 `--yt-service` |
| 休止 | 消费者发言到服务方回复的等待 | 服务方谱线上的粗短条，长度按时间；超过 120 秒用不满色并标时长 |
| 断谱 | 两条消息间隔超过 30 分钟 | 坐标轴画 `//` 断开 |
| 坐标 | 时间 | 相邻音符最小间距 18px；放不下时改为按顺序等距，只在首尾和断谱处标时间 |

- 尺寸：宽度跟随容器（风险详情约 400px），高度约 150px。
- 文字只有谱线名、时间、等待时长和图例“升温 / 降温 / 等待”。
- 可访问：图形 `aria-hidden`，下方消息列表是完整等价内容，键盘在消息列表上移动；聚焦某条消息时对应音符同步高亮。
- 系统消息不画音符。

## 3. AI 接待全景

### 3.1 解决什么

项目默认 AI 自动接待。AI 同时接待很多会话时，人需要一眼看到：AI 正在处理哪些、哪里开始变坏、哪些已转人工还没人接，并能直接接管。现在客服只能逐个点开会话。全景是人机协同里“人”的控制台，也是演示中让评委直接看到 Agent 工作流在运转的画面。

### 3.2 入口（已确认）

“接待”导航下，顶部标题改为“工作台 | 全景”分段切换：

- 两个视图共用顶栏六个指标（AI 接待、自动回复率、转人工、平均首响、建议采纳率、待处理风险），它们本来就是全景的汇总。
- 进入“接待”默认打开工作台，记住上次选择；路由 `/support?view=panorama`，刷新保留。
- 全景中点“打开会话”切到工作台并选中该会话（`/support?conversation=...`）。
- 导航七项不变。

│ 客户 ├──────────────────────────────────────┬───────────────────────┤
│▶接待 │ [全部][有风险 5][等待超时 0]   图例   │ 会话预览              │
│ 风险 │ ┌ 待人工 ─────────┐┌ 人工处理中 ────┐ │ 色号 魏h** [待人工]   │
│ 工单 │ │ ▮ ▮ ▮           ││ ▮ ▮ ▮ ▮        │ │ [接管] [打开会话]     │
│      │ └─────────────────┘└────────────────┘ │ 转人工原因            │
│ 知识 │ ┌ AI 接待中 ─────────────────────────┐ │ AI 处理步骤           │
│Prompt│ │ ▮ ▮ ▮ ▮ ▮ ▮ ▮ ▮ ▮ ▮ ▮ ▮            │ │ 最近消息              │

- 墙面：上排“待人工”“人工处理中”并排，下排“AI 接待中”占满整行。转人工时色块从下排移到左上，接管后移到右上，移动路线就是处理流程。
- 预览栏 384px；宽度小于 1180 时移到墙面下方；小于 760 时泳道改为单列，顶栏指标隐藏。
- 工具行：筛选“全部 / 有风险 N / 等待超时 N”，不符合的色块淡化到 22%，不隐藏、不跳位；右侧图例“平稳 / 不满 / 激烈 / AI 处理中 / 高风险”。
- 顶栏右侧“实时”状态点，点击可暂停刷新（再次点击恢复）。
- 泳道头：名称、数量；待人工显示“最长等待 m:ss”；AI 接待中显示“处理中 n　排队 n”（后端最多并行 4 个自动接待任务）。

### 3.4 色块单元

```
   ılılı       ← AI 正在处理时，颜听 Logo 的五根竖条律动
  ╱▔▔▏●       ← 情绪色号 md + 高风险圆点
 ▕▓▓▓▏
 ▕███▏
  ‿‿‿          ← 底部投影
  魏h**
  0:09         ← 等待计时；不在等待时显示最后活动时间 HH:MM
```

| 状态 | 表现 |
|---|---|
| AI 处理中 | 色号上方竖条律动；结束即停 |
| AI 排队 | 无律动，等待计时照常 |
| 等待中 | 计时 m:ss；≥60 秒不满色，≥120 秒风险色加粗（与 `response_wait` 阈值一致） |
| 已选中 | 香槟金浅底 + 金色描边 |
| 新消息 | 最新色带长出 420ms |
| 换泳道 | FLIP 位移 560ms，其他色块让位 |
| 会话结束 | 缩小淡出 380ms 后移除 |

排序必须稳定，避免墙面跳动：

- 待人工：等待最久的在前。
- AI 接待中：高风险在前，其余按进入泳道的先后，不因新消息重排。
- 人工处理中：按接管先后。

色块是按钮：`aria-label` 写“昵称，泳道，情绪序列，高风险”；方向键在色块间移动，Enter 选中，T 接管当前色块。

### 3.5 预览栏

1. **头部卡**：色号 lg、昵称、泳道标签（AI 接待中 / 待人工 / 人工 · 处理人）、细分场景 · 商品、当前情绪、等待计时；底部操作“接管”（人工处理中不显示）和“打开会话”。
2. **转人工原因**（仅待人工）：原因 + 触发原话。原因取值：客户要求人工、就医 · 安全转人工、投诉风险、情绪激烈、核验未通过、超时。
3. **AI 处理步骤**：安全检查 → 读取轨迹 → 知识检索 → 起草 → 核验 → 发送。进行中的步骤实时计时，完成的显示耗时，安全转人工停在“安全检查”并标“转人工”。空闲时显示“上一轮 AI 处理”和总耗时。
4. **最近消息**：最近 6 条。消费者消息带情绪点和文字；AI 回复金色浅底、标“智能助手”；人工回复浅紫底、标处理人；系统消息居中灰条。
5. 选中的会话结束后，预览显示“未选择会话”。

### 3.6 数据与接口

新增 `GET /api/support/reception/panorama`：

| 字段 | 说明 | 来源 |
|---|---|---|
| `conversationId`、`buyerAlias`、`scene`、`productName` | 基本信息 | 现有会话与订单 |
| `lane` | `ai` / `wait` / `human` | AI 模式 → `ai`；人工模式且转人工后还没有人工回复 → `wait`；已有人工回复或客服主动接管 → `human` |
| `handler` | 处理人 | 接管审计 |
| `emotionBands` | 最近 6 条消费者消息情绪 | 现有逐条情绪 |
| `highRisk` | 是否有有效高风险 | 现有风险事件 |
| `waitingSince` | 最后一条消费者消息之后还没有服务回复时的起点；系统转人工提示不算回复 | 现有 `response_wait` 计算 |
| `handoffReason`、`handoffQuote` | 转人工原因与原话 | `service_reception_handoff` |
| `aiJob` | `queued` / `running`，当前步骤、各步骤已用时间 | 任务表 + 运行中步骤登记 |
| `lastRun` | 上一轮各步骤耗时与结果 | 审计 `trace_json` |
| `lastActivityAt`、`laneEnteredAt` | 显示与排序 | 消息与模式切换时间 |

- **范围**：未结束的本地会话，且最近活动在 `panorama_active_window_minutes` 之内（默认 120；演示库可设 0 表示不限）。官方历史会话不进入全景。
- **运行中步骤登记**：在 `grounded_workflow.py` 的 `tracked(name, handler)` 和 `auto_reception.py` 的安全预检处，向进程内登记表写入“任务 ID → 当前步骤、开始时间”，接口读取。不新增数据库表。节点名映射为六个显示步骤（来源与字段校验、独立事实核验合并为“核验”；有图片时“图片读取”并入“读取轨迹”）。
- 刷新沿用工作台轮询节奏，页面隐藏时暂停（`e697e8d` 已有机制）；后续可改为事件流。
- 接管复用现有接管接口（接管时取消未发送的 AI 任务，现有逻辑）；最近消息复用现有消息接口，只在选中时请求。
- 契约变更后重新生成前端类型。

### 3.8 演示方式（手动）

全景只展示真实运行的会话，不在前端回放冒充 AI 处理。演示时在客户页手动发消息：

**准备**

1. 用 P0-4 的重置脚本恢复演示库。演示库里预先准备 6–8 个已由 AI 完成回复的普通会话，墙面开场不空。
2. 重置时把演示会话的时间整体平移到“当前时间前若干分钟”，避免出现“等待 300 小时”。只改演示库本地会话，不动官方源数据。
3. 浏览器开两个窗口：左边客户页，右边“接待 → 全景”。

**剧本**（客户页每段都新建会话，原话取自官方数据）

| 会话 | 依次发送 | 预期 |
|---|---|---|
| A 普通咨询 | “你好，我的面膜发货了吗？单号多少，麻烦了” | 色块出现在 AI 接待中，竖条律动，预览显示六步进度，AI 回复后计时停止 |
| B 投诉升级 | “你们咋回事？！我订单买了面霜和洁面泡沫两样，箱子里只有洁面泡沫！” → “照片给你，最好快点解决，不然我直接投诉到平台，麻烦了” | 第二句后色带变红、出现高风险点，停在“安全检查 · 转人工”，色块移到待人工，原因“投诉风险” |
| C 就医 | “必须给我个说法！用了你们面膜脸过敏，红肿刺痛，我人现在在医院！” | 直接安全转人工，原因“就医 · 安全转人工” |
| D 不良反应自述 | “在吗？急！昨晚用了面膜，今早额头又红又痒，是不是过敏了” | 按当前规则留在 AI 接待并显示高风险点，演示由人决定是否接管 |
| E 要求人工 | 点客户页“转人工” | 进入待人工，原因“客户要求人工” |

然后在全景点 B 的“接管” → 移到人工处理中 → “打开会话”进入工作台回复。

如果某一步的实际结果与“预期”不一致（例如 B 未转人工），按当前规则记录为规则缺口，不在前端补造状态。

### 3.9 验收（端到端）

先列失败方式：

1. 色块泳道与会话模式不一致（已人工回复仍在“待人工”）。
2. 接管后旧 AI 任务仍发出回复。
3. 排序随每条新消息抖动。
4. 等待计时在服务回复后不停止，或把系统转人工提示当作回复。
5. 官方历史会话混入全景。
6. 页面隐藏后仍在轮询。
7. 步骤进度停在中间（任务已结束但登记表未清理）。

- 悬停列表行：主图中该会话消息所在的小时柱提亮，其余降到 40%，对应菱形放大。
- 点击主图菱形：选中对应列表行并滚动到可见。
- 键盘：缩略条两端把手可聚焦，方向键每次移动 1 小时，Shift + 方向键移动 1 天。
- 时间段写入 URL（`from`、`to`），刷新保留。
- 验收：筛选后面板计数与列表行数一致；清除后恢复。

### X-2 共享元素过渡

- 风险列表行的迷你声纹 → 详情里的服务乐谱；全景色块 → 工作台中对应会话。
- 用浏览器原生视图过渡（`document.startViewTransition` + `view-transition-name`），时长 320ms；不支持的浏览器直接切换。
- 作用：让人看出“这是同一份数据换了尺度”。

### X-3 服务乐谱回放

- “对话回放”右上角 ▶：游标沿时间轴移动，音符和消息按顺序出现，客服介入处竖线落下。
- 速度 1× / 4×；空格暂停 / 继续；结束后恢复完整显示。
- 时间压缩：每条消息 0.8 秒，等待按对数比例缩放，避免长时间空白。
- 只在用户点击后播放；适合演示视频录制。

### X-4 AI 状态即品牌、核验盖章

- 插件生成回复时，插件标题栏的颜听 Logo 五根竖条律动（读取 P1-3 已有的 SSE 阶段事件），完成即停；与全景色块律动一致。
- 核验通过后，引用了事实的片段金色下划线从左到右依次画出（每段 180ms，间隔 80ms），卡片右上角淡入“已核验”小章（200ms）。
- 核验未通过时不出现小章，沿用现有失败原因展示。

### X-5 采用飞入输入框

- 点“采用”：建议正文的副本从卡片平滑移动到输入框（300ms），随后写入输入框并聚焦，输入框描边高亮 600ms。
- 只填草稿，仍需客服自己点发送；动作本身表达“采用不等于发送”，不加说明文字。

### X-6 实时事件反馈

- 风险页“实时”范围：新增高风险信号时，菱形从上方落入标记带（280ms），对应行插入列表顶部并闪一次香槟金浅底（1.2 秒淡出）。
- 全景：新消息色带长出、换泳道位移（第 3.4 节）。
- 只由真实事件触发。

### X-7 承诺倒计时环

- 插件画像卡、风险详情承诺卡、服务轨迹承诺泳道：期限前加 16px 圆环，表示从承诺到期限的剩余比例。
- 剩余不足 24 小时为不满色；已到期为风险色实心并写“已到期”。文字始终保留，不只靠颜色。
