# 情绪应对与投诉风险 SOP（内部）

> 虚构夹具：本文件不是安克官方 SOP，仅用于本 Demo 的检索与证据链路联调。
> **内部资料**：客户接口不得返回本文件原文。

适用地区：全球
版本：1.3.0

## 两个独立维度

情绪与投诉风险是**两个独立字段**，不得合并：

- `emotion_level`：`calm` / `dissatisfied` / `angry` / `unknown`
- `complaint_risk`：`flagged` / `not_flagged` / `unknown`

## 分策略应对

| 情绪 | 沟通策略 |
|---|---|
| `calm` 平稳 | 正常推进，直接给出结论与下一步 |
| `dissatisfied` 不满 | 先回应具体不满点，减少重复追问，避免模板化回复 |
| `angry` 愤怒 | 简短安抚后继续处理可自主完成的事项；不使用长篇解释 |
| `unknown` 未知 | 保持中性，先确认事实 |

## 关键规则

1. **愤怒本身不触发人工转接。** Agent 应先安抚，并继续完成查询、排障等允许的动作。
2. 投诉风险单独标记，用于提醒与复核判断，**不作为自动转接开关**。
3. 情绪只影响沟通策略，**不得**改变质保规则、赔付条件或办理结论。
4. 不得因为用户情绪激烈就承诺退款、赔偿或加急。

## 升级到人工确认的条件

满足下列任一条件时才进入人工确认：

1. 用户明确提出投诉、要求赔偿或声称将向监管/媒体反映。
2. 用户明确要求人工处理。
3. 安全风险（设备冒烟、起火、漏电、电池鼓包等）。
4. 补问补查后，办理所必需的事实仍无法确认。
5. 知识依据冲突，或依据与订单数据矛盾且无法解决。

## 禁止事项

- 不得用情绪等级推断用户「是否会投诉」，也不得把它固化为用户标签。
- 不得为了让指标好看而反复拒绝用户的人工请求。
