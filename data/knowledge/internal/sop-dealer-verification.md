# 经销商授权核验 SOP（内部）

> 虚构夹具：本文件不是安克官方 SOP，仅用于本 Demo 的检索与证据链路联调。
> **内部资料**：客户接口不得返回本文件原文。

适用地区：全球
适用渠道：第三方卖家、电商平台
版本：1.5.0

## 适用场景

仅用于**需要确认购买渠道**的场景，例如：

- 订单在系统中未命中。
- 用户陈述从第三方卖家或非官方店铺购买。

不是每位用户的必填步骤。官方渠道购买的订单无需执行本 SOP。

## 核验顺序

1. **优先读取已有信息**：订单记录、购买凭证、用户已提供的内容。
   信息齐全时直接匹配，**不重复追问**用户。
2. **自动匹配**：按「国家/地区精确匹配、卖家名称模糊匹配」查询授权名录。
3. **仅在缺失或歧义时补问**：询问实际购买店铺名称或请用户补充凭证。
4. **补充后重查**：仍无法唯一确认时，进入 Demo 后台复核。

## 匹配结果处理

| 匹配结果 | 状态 | 处理 |
|---|---|---|
| 唯一匹配 | `authorized` | 记录标准名称，继续后续质保判定 |
| 明确不匹配 | `not_authorized` | 说明原因，提供可行替代路径 |
| 多个候选 | `multiple_matches` | 不得任选其一，补问实际店铺或交后台复核 |
| 查询失败 | `query_failed` | 记录失败，允许重试或转人工；**不得判定为非授权** |
| 无匹配 | `unknown` | 补问凭证；仍无法确认交后台复核 |

## 保存要求

- `seller_name_raw`：用户实际提供或凭证读取的**原始店铺名**，有输入就必须保存。
- `seller_name_standard`：仅唯一核验成功时填写标准名；无唯一匹配时**留空**，不得虚构。
- 标准名**不得覆盖**原始名。

## 严格禁止

1. **不得向用户展示授权经销商名单让用户挑选**来证明授权。
   自我声明或点击选择不构成授权证据。
2. 不得把「订单未命中」直接判定为非授权。
3. 不得用相似度分数直接断定授权；相似度只是候选排序信号。
4. 不得因为用户提供了某个知名店铺名称就跳过名录核验。
